# API Coverage — Anthropic Claude API (Phase 13)

> Full coverage by default. Opt-outs are explicit, reasoned decisions.
> Scope: the only external API this phase touches is the Anthropic Messages API, through the classification and drafting calls that already exist (Phase 5, `.planning/milestones/v1.0-phases/05-ai-drafting-classification/COVERAGE.md`). Phase 13 adds NO new capability: it selects a second structured-output schema and a second system block by the row's kind, and bumps the drafting prompt to `p5`. No package is installed; `@anthropic-ai/sdk` stays at its installed version (13-RESEARCH.md, Standard Stack). ClickSend, Twilio, Resend and Supabase surfaces are unchanged and are not re-opened here.

| capability | decision | reason |
|---|---|---|
| `messages.parse` structured outputs — lead classification schema | INTEGRATE | 13-04 Task 2 — `zodOutputFormat(LeadReplyClassification)` chosen when `row.leadId` is set; re-validated with `safeParse` (D-05) |
| `messages.parse` structured outputs — quote classification schema | INTEGRATE | unchanged from Phase 5; the quote arm is byte-for-byte what it was (D-17) |
| `messages.parse` structured outputs — drafting body, prompt `p5` | INTEGRATE | 13-02 Task 1 — the lead instruction block and lead facts ride the existing call (D-13) |
| System prompt selected per row kind (lead vs quote instructions) | INTEGRATE | 13-04 Task 2 — one `ask()` with the triple passed in; definitions derived from `Record<Label, string>` so an undescribed label is a type error |
| Prompt caching (`cache_control: ephemeral` on the drafting stable prefix) | INTEGRATE | unchanged; the lead system block is a second stable prefix per tenant — stable client-voice block first, volatile lead facts last (CLAUDE.md) |
| `CLASSIFY_MODEL` / drafting model ids | INTEGRATE | unchanged — no model change in this phase; exact ids, no date suffix |
| Typed errors, SDK `timeout`/`maxRetries`, `usage` counters, `stop_reason` | INTEGRATE | unchanged from Phase 5; the lead arm goes through the same transport and the same `unparseable` path |
| Raw `messages.create` (free-form text, no output schema) | OPT-OUT | free-text LLM parsing is on the project's What-NOT-to-Use list; every call stays schema-bound through `parse` |
| Tool use (`tools` parameter, tool runner, `betaZodTool`) | OPT-OUT | the absence of the `tools` key is the D-13 privilege boundary; `tests/classification-privilege.test.ts` pins it |
| Deprecated `output_format` parameter | OPT-OUT | replaced by `output_config.format`; `grep -c "output_format"` is 0 in the classifier (13-04 acceptance) |
| Streaming (`messages.stream`) | OPT-OUT | short completions inside a per-minute tick; buffered parse is simpler and schema-safe |
| Message Batches API | OPT-OUT | drafts must land within the tick with review lead time; lead volume is a handful per day |
| Token counting endpoint | OPT-OUT | usage read from responses; no pre-flight budgeting at this volume |
| Extended thinking (`thinking` parameter) | OPT-OUT | omitted on both calls; the classification token cap already fits the default |
| Sampling params (`temperature` / `top_p` / `top_k`) | OPT-OUT | rejected by the current models with a 400 (Phase 5 Pitfall 1); none sent |
| Assistant prefill | OPT-OUT | removed on current models; the lead classifier is designed around structured outputs, not prefill (CLAUDE.md) |
| Free-text summary field in the classification schema | OPT-OUT | D-05: no free-text summary is stored from the model — three fields (label, urgency, confidence), no prose |
| Files / PDFs / citations / vision inputs | OPT-OUT | inputs are short SMS bodies and quote facts |
| Computer use / MCP connector / web search tool | OPT-OUT | no agentic surface; least privilege for a classifier whose output drives a state machine |
| A tradie-facing summary generated by the model (digest or SMS) | OPT-OUT | research Open Question 5: the 06:30 digest is the operator's email and is built from counts in fixed words, with no model call |
