# Phase 15 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** the four operator surfaces Phase 15 adds or extends — (1) the new `/leads` lead queue (CON-05, D-01), (2) the per-client missed-call log on `clients/[id]` (CON-06, D-02), (3) the missed-call figures block on `/reports` + `/reports/[client]` with the design-partner CSV export (RPT-04/RPT-05, D-03/D-04/D-10), plus the printed monthly report's optional missed-call figures, and (4) the one overdue line the 06:30 digest's Leads section gains (D-09). Sources: 15-CONTEXT.md D-01..D-04, D-08, D-09, D-10; ROADMAP Phase 15 criteria 1–4; the shipped console in `src/app/globals.css`, `(console)/queue/{page,queue-card}.tsx`, `(console)/inbox/{page,create-job-form}.tsx`, `(console)/clients/[id]/page.tsx`, `(console)/reports/page.tsx`, `(console)/reports/[client]/page.tsx`, `(console)/components/label-guess.ts`, `src/core/aging/{stall-policy,stalled-digest}.ts`; the approved 06-UI-SPEC and 07-UI-SPEC (still binding); `tests/layout-contract.test.ts`, `tests/console-error-leak.test.ts`, `tests/lint-ban.test.ts` (CLIENT_REACHABLE).

**No questions were asked.** Every field below is pre-populated from the upstream decisions and the code, and each decision this contract makes on its own is marked **[decision]** with its reason.

**The founder will see these pages with ZERO rows.** Production has no leads, no missed calls and nothing armed (12-09 override). The empty states in this contract are not edge cases — they are the first thing the UAT phone shows, so each one says what the screen is for and what will appear.

**Design-system state: ESTABLISHED, not greenfield.** Hand-rolled CSS in `src/app/globals.css` on the M1 palette (09-UI-SPEC D-04, Graphite since 19 Sep 2026). This phase declares **zero new colours, zero new fonts, zero new libraries, zero new npm dependencies** (no chart library — the hour/weekday split is a table). New CSS rules are allowed only where no existing class fits, and none are expected (see "Class budget").

**Class budget [decision]:** zero new CSS classes are required for the four surfaces. Every block maps onto a shipped rule (listed per surface below). If an executor finds a genuine gap, the rule goes in `globals.css` under a `/* --- Phase 15 --- */` comment, uses `var(--…)` tokens only, and is named in the plan — never an inline `style`, never a hex.

**Nav [decision]:** `/leads` is one new `<Link href="/leads">Leads</Link>` placed **third** — after `Queue`, before `Audits` — because it is the third screen with a clock on it (a lead past its next-touch deadline), and the nav's order is argued by clocks, not alphabet. **No count badge**: a cross-tenant count rendered in the chrome of every authenticated page is what A5 forbids (the `Reports` precedent, U-8); the overdue count lives on the page's count line and in the digest line (D-09). The link inherits the existing 44px `.nav nav > a` rule. The row already scrolls sideways at 390px; one more item is more scroll, not a layout change (layout-contract's CSS assertions are untouched). Housekeeping the plan must include: add `/leads` to `src/app/robots.ts` disallow list, to the console path list in `src/proxy.ts`, and to the `it.each` lists in `tests/marketing-metadata.test.ts` / `tests/proxy-host-routing.test.ts`.

## Spacing Scale

Phase 2/6/7 rules carry forward unchanged; shipped rules with ad-hoc rem values are grandfathered. New markup uses only the existing classes, which already sit on this scale (rem at 16px root):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (0.25rem) | Gap inside `.touch-when` / `.touch-line` chip rows (existing `gap: 0.25rem 0.5rem`) |
| sm | 8px (0.5rem) | `.controls` stack gap; `.meta` bottom margin; `.metrics` row gap |
| md | 16px (1rem) | `.controls` block margin; `.metrics`/`.profile` top margin; table top margin; section gaps |
| lg | 24px (1.5rem) | `.report-figures` grid gap (existing) |
| xl | 32px (2rem) | `.report-figures` bottom margin (existing) |
| 2xl / 3xl | 48px / 64px | Reserved — not used this phase |

Exceptions:
- **44px (2.75rem) minimum tap target** on every control: `button` (base rule), `.button-quiet` (links and buttons), `.controls .button`, `.disclosure > summary`, nav links. Nothing tappable on `/leads` or the missed-call log may be smaller — both are worked one-handed on a phone. The "Show older calls →" pagination link and the "Approve the next touch →" deep link are `.button-quiet` anchors for exactly this reason (an inline text link is ~24px).
- **One column, no horizontal scroll** on `/leads` and in the missed-call log: cards and `.touch-list` rows wrap. The only sideways-scrolling boxes are the two compact split tables and the `/reports` overview table, each inside the existing `.table-scroll` (`tabIndex={0}`, `role="region"`, `aria-label`).
- Phone stacking below 22.5rem rides `.touch-when--stack` (badge wraps inside an intact border); the `.draft-card` padding (0.85rem) and `main` padding (1.25rem) are grandfathered.

## Typography

Weights for new work: **400** and **600** only (the 02/06 rule; `label`/`legend` at 500 are grandfathered). Exactly these sizes, all from existing rules:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / reply body / `.profile dd` | 16px (1rem) | 400 | 1.5 (inherited) |
| Meta / evidence (`.touch-meta`, `.hint`, `.meta` inside `.muted`, `.metrics dt`, `.skip-confirm`, `.zone-note`, `.report-figure-note`) | 14px (0.875rem) | 400; `<strong>` 600 for the one emphasised fact (the caller's number, the touch number) | 1.5 |
| Badge micro-type (`.badge`) and `th` | 12.8px (0.8rem) uppercase, 0.03em tracking | 400 | existing |
| Heading h1 24px (1.5rem) / h2 browser default / figure value `.report-figure dd` 24px | 24px | 600 | 1.2 |

Rules:
- **Times are in the TENANT's zone with the zone named** (`formatInTenantZone(at, tz)` + ` (${tz})`) on `/leads` (mixed tenants — every card names its zone, the queue rule) and in the digest line. On `clients/[id]` and `/reports/[client]` the zone is named once in the h2's `.zone-note` and the rows carry the time only (the Quotes-section rule). `relativeToSlot` (`due in 2h` / `overdue`) sits BESIDE an absolute time, never instead of it.
- **Caller mobiles** render in the local spaced form `toLocalSpacedMobile(e164)` → `0412 345 678` — the form the create-job sheet already shows and writes to ServiceM8, with tabular digits inherited from `.num` where used in a cell. **[decision]** Operator-only surfaces show the full number, as the inbox shows the full `from` address (the inbox's header argument: this page is behind auth + the operator allowlist and renders only what the person deciding must read). No visual masking: a masked number cannot be rung back or matched by eye against ServiceM8. The number is NEVER logged (schema header rule) and never reaches a client-facing artefact (the report sheet, the CSV, the digest).
- **Every label comes from a map, never `.replace('_', ' ')`** (house rule): the text-back outcome chips, the skip-reason words, the lead resolution chips, the urgency tier. Each map is pinned by a pure test that reads the schema vocabulary and fails on a member without an entry (the `tests/lead-labels.test.ts` precedent).
- **Figures with denominators**: the value is the rate (`formatRateBp` → `12.5%` / `—`), the evidence line is `{n} of {d} {noun}` in `.muted` 14px, never `(n/d)` beside a dash. The null-denominator evidence is a sentence, not `(0/0)` (the `MetricCell`/`MetricRow` rule).
- Durations: whole seconds `median 42 s · P90 118 s` (space before the unit, tabular digits via `.num` in table cells; prose otherwise).

## Copywriting Contract

Voice: plain, operator-facing, no exclamation marks, no jargon. A classifier's label is phrased as a guess on every surface (`reads as …`). Error copy = what happened + what to do next; the caught value is always discarded (WR-08/T-2-02). Every sentence below is FIXED; the only interpolations are client names, caller numbers (operator-only surfaces), integers, formatted times and the fixed words from the maps.

**Sort & grouping [decision]:** one flat list, no group headings — ordered by next touch `scheduled_at ASC NULLS LAST, first_missed_at ASC`, in SQL before the LIMIT (the queue's sort-before-cap rule). The deadline chip IS the grouping; a heading per tier would push the first card below the fold on a phone. Cross-client by construction (`forAllTenants_…` read behind `requireOperator()`; names and zones through the operator's own JWT, the queue page's two-authority pattern). The deadline tier is derived ONCE on the server from the render's single `now` with `deriveUrgency` — the same function the count line and the digest's overdue predicate use, so three surfaces cannot disagree about "overdue".

**Why the create-job button is the accent control [decision]:** of the three actions, creating the job is the money moment and the one that writes somewhere irreversible; approving a touch is a navigation (the approve itself happens on `/queue`, with the message visible); closing is terminal but quiet. One accent per card, like the queue's approve.

### Accessibility notes
- Every chip is text; colour reinforces (WCAG 1.4.1). Low-confidence suffix (` — a guess`) is in the chip text, not a tooltip.
