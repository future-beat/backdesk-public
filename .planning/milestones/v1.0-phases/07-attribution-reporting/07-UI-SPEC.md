# Phase 7 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** the Phase 7 console surfaces — the cross-client `/reports` overview (RPT-03, D-14/D-15/D-16), the per-client `/reports/[client]` detail with metrics, frozen-report list, Generate action and fee schedule (RPT-02/RPT-03, D-11/D-13/D-14), the printed A4 monthly report at `/reports/[client]/[reportId]` (RPT-02, D-11/D-12/D-13), the new nav link and the one-line link from the Phase 6 pipeline page (D-14), and the single opt-out-alarm line the 06:30 digest gains (D-16). Sources: 07-CONTEXT.md D-01..D-18, 07-RESEARCH.md Patterns 2–6 + Pitfalls 6–8 + Open Question 4, the Phase 6 UI-SPEC (approved, binding), and the shipped `src/app/globals.css`, `audits/[id]/{page.tsx,audit.css}`, `layout.tsx`, `page.tsx` (client list), `inbox/page.tsx`, `clients/[id]/page.tsx`.

**Design-system state: ESTABLISHED, not greenfield.** The Phase 2 contract decided "do NOT introduce Tailwind/shadcn mid-project"; Phases 3–6 inherited it verbatim and so does this one. Every token below is the Phase 6 token, restated so this file is self-sufficient for the checker; nothing is re-decided. This phase adds ONE page-scoped stylesheet (`report.css`, the `audit.css` twin) and a small number of new global classes listed in the Design System row; it never restyles a shipped rule.

**Discretion exercised in this contract (autonomous session — recorded, not asked):**

| # | Choice | Decision | Rationale |

## Spacing Scale

Phase 2/6 rules carry forward unchanged. Existing shipped rules with ad-hoc rem values are grandfathered — do not restyle. All NEW Phase 7 rules use this scale (rem at 16px root):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (0.25rem) | `dt`→`dd` gap in figure blocks; badge ↔ value gap inside a metric `dd`; h1 → subline |
| sm | 8px (0.5rem) | Between stacked form controls; fee-row internals; `.meta` bottom margin (existing) |
| md | 16px (1rem) | Default block spacing: between sections' internal blocks, footnote list item gap, footer padding-top, table margin-top (existing) |
| lg | 24px (1.5rem) | Gap between figure cells in the report grid; gap between the hero and the figure grid; `.report-actions` padding-top |
| xl | 32px (2rem) | Below the figure grid before the per-job table; below the subline; `.report-actions` margin-top |
| 2xl | 48px (3rem) | `.report-sheet` top padding on screen (the audit's `padding-top: 3rem`) — zero in print |
| 3xl | 64px | Reserved — not used this phase |

Exceptions:
- **44px (2.75rem) minimum touch target** on every button (`Generate report`, `Add fee`, `Print or save as PDF`), on the fee-schedule `.disclosure > summary`, and on every report-version link row (`.touch-list li` padding already yields ≥44px). Nothing tappable may be smaller — the detail page is worked on a phone.
- **Print margins:** `@page { size: A4; margin: 14mm }` — the audit value, verbatim. Not on the 8-point scale by design (paper, not pixels).
- **Table cell padding** stays on the existing `th, td { padding: 0.6rem 0.5rem }` rule — grandfathered, reused, not redeclared.
- Existing shell (`main { padding: 1.25rem; max-width: 60rem }`) grandfathered; `.report-sheet { max-width: 42rem }` matches `.audit-sheet`.
- **`.report-notes { padding-left: 1.25rem }` (20px)** — the list-marker indent for the numbered methodology footnotes `ol`. A multiple of 4 off the named scale, kept deliberately: the browser default (40px) is off-scale and wastes a fifth of a phone column; `1rem` clips two-digit markers in Safari. The only new off-scale value this phase.

## Typography

Weights for new work: **400 (regular)** and **600 (semibold)** — the Phase 2 rule. Existing 500-weight rules (`label`, `legend`) are grandfathered; no new 500 usage.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (1rem) | 400 | 1.5 (inherited from `body`) |
| Label / meta / footnote / table (`.meta`, `.hint`, `.zone-note`, `th`, `.report-notes`, `.report-footer`, figure `dt`, `.profile dt`) — **on screen**; the printed per-job table is the one exception, see the print-only rule below | 14px (0.875rem) | 400 (600 for figure `dt` and `tfoot` totals — the emphasised fact) | 1.4 (footnotes 1.5 — a paragraph the client reads) |
| Heading (h1 24px; h2/h3 browser defaults inside the existing hierarchy) and the six secondary report figures (`.report-figure dd`) | 24px (1.5rem) | 600 | 1.2 |
| Display — the hero multiple ONLY (`.report-hero dd`) | 32px (2rem) | 600 | 1.2 |

Rules:
- **Four sizes on screen, no fifth.** The audit's 32px display size was declared "used ONLY here" — the report hero is the second document in the same mould and the second legitimate use. The six secondary figures step DOWN to 24px so the hero is the only thing at display size; the audit spent 32px on four figures because it had four figures and no hero multiple.
- **Print-only exception (07-06, G-07-2): the per-job table drops to 0.7rem.** `.report-lines th, .report-lines td { font-size: 0.7rem }`, inside `@media print` ONLY — it must not appear in any screen rule, and the four screen sizes above are untouched by it. THE REASON IS THE SHEET, NOT TASTE: seven columns have one 661px budget (the width `zoom: 0.75` gives WebKit; Chromium prints 688px), and every printed job row has to be ONE LINE BOX because neither engine keeps a taller row whole at a fold. 0.75rem wraps every row at that width — measured, not assumed. 0.7rem lands at 8.4pt on both engines (11.2px at 96px/in on Chromium; 11.2px at 1px=1pt scaled by the zoom on WebKit): small print, but consistent and legible, and it is the price of no row straddling the fold. `th` keeps its 0.8rem uppercase rule ON SCREEN. [Contract correction 07-06 review, 2026-09-03, WR-05 — `cba407f` prescribed this size in §Screens and left §Typography saying "four sizes, no fifth" with the table row at 14px, so the shipped CSS matched one section and violated the other and no reader could tell which won. That is the same failure the 07-04 post-mortem in that same commit recorded: "07-04 implemented §3 verbatim — the defect was the contract."]
- Badge micro-type stays on the existing `.badge` rule (0.8rem uppercase) — reuse, never redeclare. `th` stays on its existing 0.8rem uppercase rule on screen (the print exception above is the only place it does not).
- **Money:** invoice-grade on the report and everywhere in this phase — `Intl.NumberFormat('en-AU', { style: 'currency', currency: 'AUD', minimumFractionDigits: 2, maximumFractionDigits: 2 })`, formatted from integer cents at the last moment. (The audit's whole-dollar rule is explicitly for ESTIMATES; a recovered-revenue line is a real quote total — RESEARCH Pattern 5.)
- **Rates:** one decimal place (`7.1%`), never `NaN`, never `0%` for a null denominator — `—` (`NO_VALUE`) with the evidence text `no {noun} in the window` beside it (the `computeBaseline` null-never-0 rule made visible).
- **Multiples:** one decimal + `×` (`3.4×`); `0.0×` is a real answer for a month with nothing attributed; `—` only when the fee was `$0.00`.
- **Dates on the printed report:** `d MMM yyyy`, no time component, in the client's timezone (the audit's `formatDate` argument — a timestamp claims a precision the method disclaims). **On screen** every instant renders via `formatInTenantZone` with the zone named once in a `.zone-note` beside the page's h1 (single-tenant page — the existing shortcut applies). The overview mixes tenants but shows NO timestamps, so no zone question arises there.
- **Period label:** `new Intl.DateTimeFormat('en-AU', { month: 'long', year: 'numeric', timeZone })` on `period_start` → `August 2026`.
- Every enumerated value on screen (baseline source, fee kind, value source, suppression source) renders through a **label map that fails loudly on an unknown member** — never `.replace('_', ' ')` (house rule).
- Numbers the operator compares are digits, never words; counts and their denominators are printed as `{n} of {d}`.

Voice: plain, operator-facing on screen; **client-facing on the printed report** — the tradie's language, dollars, no jargon ("attribution", "baseline", "conservative net-of-baseline" are explained the first time they appear, in a footnote, in words a plumber would use). ### Contract corrections (quick-260904-dwt, 2026-09-04)

The operator passed UAT test 6 on 2026-09-04 and immediately asked for the bar to scroll sideways rather than wrap. The 07-06 correction below was right about its premise — the page must never widen — and wrong about what that should cost: it bought a 390px document three rows and 176px of chrome, a quarter of the phone screen on `/queue`, with the two least-used items on the rows nobody looks at. The E8 row is corrected in place and tagged where it stands.

- **E8 — the wrapped bar traded page width for screen height, and the row can hold its own overflow instead.** The mechanism: a nowrap flex row cannot shrink below the sum of its items' min-content widths plus gaps (~502px with the Queue badge showing), so the surplus has to go somewhere. 07-06 spent it on height by wrapping both containers; quick-260904-dwt spends it sideways by making `.nav nav` the one box in the bar allowed to hold overflow (`overflow-x: auto`), leaving the outer `.nav` wrap in place purely as the brand-collision fallback below ~365px. This is not the `overflow-x: hidden` on the SHELL that the G-07-3 debug record's `fix_rationale` rejected: a scroll container keeps every item reachable by swipe, by programmatic scroll and by keyboard focus, where a clipped shell made `Sign out` permanently unreachable. Measured in headless Chrome over the shipped `globals.css` — 390px: document exactly 390, bar one 72px row (176px before), row box 221px against 502px of content, resting at `scrollLeft 0`, `Inbox`/`Queue`/`Audits` whole, `Reports` cut, `Sign out` at `scrollLeft 281` of 281 after one swipe and inside the box on focus, 4px of ring headroom; 604px: 72px (124px before), row 435/502; 700px: 72px, `rowScrollable false`, `navRight` 684, no fade; 320px: the wrap fallback, 124px, `Inbox` through `Reports` visible.
- **DECISION SURFACED FOR THE OPERATOR — the spec asked for four items in the first screenful and arithmetic refuses.** The brand `Quote Recovery` is 121px at 600 weight; with the 1rem gap and the 1.25rem side padding the row gets 221px at 390px, and `Inbox` + `Queue`(badge) + `Audits` + `Reports` need 262px. The one-row bar was the operator's actual complaint, so it wins, and `Reports` being partly cut IS the item-2 cue that the row scrolls. Reversible by shortening the brand or dropping a link — not by shrinking the gaps or the type, which is the trade the CSS comment refuses in writing.
- **The fade is CSS only and degrades to nothing.** `--nav-fade` is a registered `<length>` driven by `animation-timeline: scroll(self inline)`: 2.5rem while scroll range remains, collapsing to 0 over the last 15% so `Sign out` is never dimmed at the end. An inactive timeline (nothing overflows, i.e. the 700px bar) never applies the animation; an engine without scroll timelines resolves `animation-duration: auto` to 0s and `fill-mode: both` holds the 0px keyframe; an engine without `@property` leaves `mask-image` invalid, i.e. `none`. Every path is "no fade, still scrollable". No JS, and no `prefers-reduced-motion` clause because nothing moves on its own.
