## Phase Goal

**As a** the operator, **I want to** generate a Quote Leakage Audit from any prospect's read-only API key with their baseline win rate snapshotted, **so that** every sales conversation starts with the prospect's own leakage dollars and Phase 7 can later report net-of-baseline honestly.

<objective>
The audit data pipeline: the D-01 separate `prospects` model with D-03 audit-only line tables and D-04 30-day purge, the pure aggregation core (D-09 recoverable estimate, D-10 grace-period follow-up detection), the shared 90-day fetch path (D-12/D-14 — same Sm8Client, bulk joins, no N+1), the API-key prospect creation vertical through to visible figures, and the client-side baseline snapshot (D-14). The CSV fallback and the A4 print report land in plan 02-07 on top of these tables and functions.

Purpose: the audit is the sales instrument AND the attribution baseline — both must come from one tested aggregation so the numbers can never disagree.
Output: operator can create an API-key prospect and see persisted audit figures; purge job live; client baselines snapshotted.

Requirements: AUD-01, AUD-02. Decisions: D-01 (reversibility: costly — human-locked in discuss-phase; merging prospects into tenants later means a data migration plus rewriting audit queries), D-02 groundwork (link lands with the convert control in 02-07), D-03, D-04, D-09, D-10, D-12 (API half), D-14.

Flagged planner assumption (surfaced, not silent): AUDIT_RECOVERY_RATE = 0.15 is the conservative end of the D-09 15–20% band; the GTM research files contain no more specific figure. It is a one-line named-constant change if the operator prefers another value in the band.
</objective>
