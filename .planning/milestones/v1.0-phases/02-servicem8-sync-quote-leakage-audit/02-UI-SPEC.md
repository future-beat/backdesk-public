# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** the Phase 2 console surfaces — ServiceM8 connect form, per-client sync health (list badge + detail runs), auth-failed banner, synced quotes view with status filter, backfill triage checklist, prospect creation (API key / CSV with column mapping), and the Quote Leakage Audit page (the print-styled A4 sales artifact). Sources: CONTEXT.md D-05..D-16, RESEARCH.md Patterns 5–7, and the Phase 1 console conventions in `src/app/globals.css` + `src/app/(console)/`.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Phase 1 established a deliberate hand-rolled CSS system (`src/app/globals.css`: "system fonts (no webfont round-trip), large tap targets, single column"). Phase 2 extends it; do NOT introduce Tailwind/shadcn mid-project |
| Preset | not applicable |
| Component library | none — semantic HTML + the existing class vocabulary (`.badge`, `.error`, `.muted`, `.row`, `.profile`, `.button`, `.linkish`, `.field-error`, `.hint`, `.check`, table styles) |
| Icon library | none — no icons in Phase 1; Phase 2 stays icon-free (status is communicated by badge text + color, never color alone) |
| Font | System stack: `system-ui, -apple-system, 'Segoe UI', Roboto, sans-serif` (existing `body` rule — applies to the audit report too: no webfont for a page opened on a phone in a sales meeting) |

**Theming:** light + dark via `prefers-color-scheme` on `:root` custom properties (existing). Every NEW color token declared below MUST ship both light and dark values in the same `:root` / `@media (prefers-color-scheme: dark)` blocks. The audit report page forces light values under `@media print` (ink on paper).

## Spacing Scale

Declared values (must be multiples of 4). Phase 1 CSS uses ad-hoc rem values (0.35/0.6/0.85rem etc.) — those existing rules are **grandfathered, do not restyle them**. All NEW Phase 2 rules use this scale (rem equivalents at 16px root):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (0.25rem) | Inline gaps (badge ↔ text, checkbox ↔ label) |
| sm | 8px (0.5rem) | Compact spacing inside table cells, badge padding, stacked meta lines |
| md | 16px (1rem) | Default block spacing: between form fields, banner padding, section gap on detail page |
| lg | 24px (1.5rem) | Section padding, gap between detail-page sections (profile / sync health / quotes / triage) |
| xl | 32px (2rem) | Major breaks: audit report section separation on screen |
| 2xl | 48px (3rem) | Page-level top spacing on the audit report (screen only) |
| 3xl | 64px | Reserved — not used this phase |

Exceptions:
- **44px minimum touch target** on all buttons and the triage checkboxes' tap area (existing `button { min-height: 2.75rem }` rule; triage rows wrap each checkbox in a ≥44px-tall label).
- **Print sheet**: `@page { size: A4; margin: 14mm }` on the audit report — millimetres, outside the px scale by nature.
- Existing `main { padding: 1.25rem; max-width: 60rem }` shell is grandfathered.

## Typography

Two weights for new work: **400 (regular)** and **600 (semibold)**. Existing Phase 1 `label`/`legend`/`th` at 500 are grandfathered; do not introduce NEW 500 usage — new emphasized text (badges, figure labels, table headers in new sections) uses 600 or the existing classes.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (1rem) | 400 | 1.5 (inherited from `body`) |
| Label / meta | 14px (0.875rem) | 400 (600 when it labels a figure) | 1.4 |
| Heading (h1, report section heads) | 24px (1.5rem) | 600 | 1.2 |
| Display (audit headline figures only) | 32px (2rem) | 600 | 1.2 |

Rules:
- The 32px Display size appears **only** on the audit report's four headline dollar/count figures. Nothing in the operational console uses it.
- Badge/table-header micro-type stays on the existing `th`/`.badge` rules (0.8rem uppercase, grandfathered) — reuse the classes, never redeclare the size.
- Money renders via `Intl.NumberFormat('en-AU', { style: 'currency', currency: 'AUD', maximumFractionDigits: 0 })` on the audit report (whole dollars — it's a sales estimate, cents undermine it) and with cents (`minimumFractionDigits: 2`) in the operational quotes table. Never string-concatenate `$`.
- Dates in the console render in the client's IANA timezone via the existing `Intl.DateTimeFormat('en-AU', …)` pattern from `clients/[id]/page.tsx`; the audit report shows dates as `d MMM yyyy` (no times — times imply precision the data doesn't have, per D-10's honesty stance).

| Secondary (30%) | `--line` + `--muted` #e2e5ea + #626875 / #262b33 + #9aa2b1 | Borders, table rules, neutral badges, meta text (existing — the console has no card fills; structure is drawn with borders) |

Accent reserved for: links, the one primary button per screen (`Connect ServiceM8`, `Save eligibility`, `Generate audit`, `Confirm mapping`), the active state of the quote status filter, and the single **Recoverable estimate** figure on the audit report. Never for badges, banners, table chrome, or secondary buttons.

Badge state mapping (D-07) — modifier classes on the existing `.badge` (border + text colored, background stays `--bg`; state is always also spelled out in the badge text, never color-only):

| State | Class | Color |
|-------|-------|-------|
| healthy | `.badge--ok` | `--ok` |
| degraded | `.badge--warn` | `--warn` |
| auth-failed | `.badge--error` | `--error` |
| never-synced | `.badge` (base) | `--muted` (existing neutral) |

Print (audit report): everything renders `#16181d` on white regardless of scheme; the single permitted color is `--accent` (light value #1f6feb) on the Recoverable estimate figure. Badges/banners never appear on the report.

## Copywriting Contract

Voice: plain, operator-facing, no jargon, no exclamation marks. Error copy = what happened + exactly what to do next. The audit report copy is prospect-facing: dollars-first, honest, no hype.

| Element | Copy |
|---------|------|
| Primary CTA — connect form | `Connect ServiceM8` (re-key after auth failure: `Save new key & resume`) |
| Primary CTA — triage | `Save eligibility` |
| Primary CTA — prospect/audit | `Generate audit` (CSV path intermediate step: `Confirm mapping`) |
| Connect form hint | `Paste a private API key from this client's ServiceM8 account (Settings → API Keys). The key is verified with a live call before it's saved.` |
| Connect verifying (pending) | Button disabled, text `Verifying key…` |
| Connect verify failed | `ServiceM8 rejected this key. Check it was copied in full from Settings → API Keys and try again.` (inline `.field-error` under the key input) |
| Connected state | `Connected — key ending in {last4}` + last-successful-sync time (plaintext key is never rendered, per RESEARCH Pattern 4) |
| Auth-failed banner (D-05) | Heading: `ServiceM8 connection failed — follow-ups paused.` Body: `The API key was rejected on {date}. Save a new key below to verify and resume automatically.` Persistent, not dismissible; clears only on verified re-key (D-08) |
| Empty state — quotes (never-synced) | Heading: `No quotes yet.` Body: `Connect ServiceM8 above — the first sync runs within 5 minutes and pulls the last 90 days.` |
| Empty state — quotes (synced, none open) | `No open quotes right now. Switch the filter to see won and lost quotes.` |
| Empty state — filter returns nothing | `No {won/lost} quotes in the synced history.` |
| Empty state — sync runs | `No sync runs yet.` |
| Empty state — triage | Section renders `Nothing needs review.` when zero quotes are `needs_review` (section stays visible so the operator knows triage is done, not missing) |
| Empty state — audits list | Heading: `No audits yet.` Body: `Create a prospect to generate their Quote Leakage Audit.` + `New audit` button |
| Error — sync run failure detail | Show the classified outcome (`auth failed` / `rate limited` / `server error` / `network error` / `response parse error`) + timestamp; never a raw stack trace, never the API key or request headers |
| Error — CSV unmappable column | `Couldn't find a column for {field name}. Pick it from the dropdown or re-export the Job List from ServiceM8 reporting.` |
| Error — CSV row validation | `{n} rows skipped — {reason}. The audit will be generated from the {m} valid rows.` (proceed-with-warning, operator confirms) |
| Error — audit generation (API path) | `Couldn't fetch this prospect's data: {classified reason}. Check the read-only key or fall back to a CSV export.` |
| Triage explainer (D-15) | `Backfilled open quotes start as "needs review". Tick the quotes this client wants chased — nothing is followed up until you save it here.` |
| Audit report title | `Quote Leakage Audit — {Business Name}` with subline `Last 90 days · prepared {d MMM yyyy}` |
| Audit figure labels | `Quotes issued` / `Total quoted value` / `Value never followed up` / `Recoverable estimate` (+ `Baseline win rate` as a secondary stat) |
| Audit methodology footnote (D-10, API path) | `How this was measured: quotes issued in the last 90 days of your ServiceM8 data. "Never followed up" means no note, activity, or status change within 3 days of the quote being sent — follow-ups made outside ServiceM8 aren't visible here, so the real number may be lower. The recoverable estimate applies a conservative {RATE}% recovery rate to the never-followed-up value.` |
| Audit methodology footnote (CSV addendum) | `This audit was prepared from a CSV export, which doesn't include notes or activity — "never followed up" here means no status change after the quote.` |
| Destructive confirmation | **None this phase.** No destructive actions exist: triage ticks are reversible saves, prospects have no delete UI in v1, and data purge (D-04) is an automatic cron job with no UI trigger. |

`{RATE}` is `AUDIT_RECOVERY_RATE` from `src/core/audit/constants.ts` (research recommends 0.15) — the report must render the constant, never a hard-coded string, so the number and the footnote can never disagree.

## Screens & Interaction Contract

New/extended surfaces, all inside the existing `(console)` shell except where noted:

### 1. Client list — sync health columns (extends `(console)/page.tsx`, D-07)
- Add two columns to the existing table: **Sync** (state badge per the mapping above) and **Last sync** (relative or short timestamp in the client's timezone; `—` for never-synced).
- Auth-failed rows additionally show the badge; no row-level banner (banner lives on detail). Row remains a normal table row — no color-washed rows.
- Badge is derived state (never stored), per RESEARCH Pattern 5.

### 2. Client detail — connect form + sync health + quotes + triage (extends `clients/[id]/page.tsx`)
Section order top-to-bottom (single column, phone-first): auth-failed banner (when applicable, directly under the h1 row) → profile (existing) → **ServiceM8 connection** → **Open quotes** (with triage when applicable) → **Recent sync runs**.
- **Connection section:** not-connected shows the key form (`password`-type input, `autocomplete="off"`); connected shows `key ending in {last4}` + health badge + last sync + a `Replace key` disclosure revealing the same form. Save = server action; pending state disables the button (`Verifying key…`); success reloads with connected state; auto-resume is invisible plumbing (D-08) — the UI truth is: banner gone, badge healthy.
- **Quotes section (D-16):** table defaulting to open (`Quote` status). Filter = link-group `Open · Won · Lost · All` driven by a `?status=` search param (server component, no client JS); active filter link in `--accent`, non-active in `--muted`. Columns: Job # (`generated_job_id`), Description (truncated, see UI Considerations), Contact, Value (AUD with cents), Quote date, Status badge (neutral base `.badge`), and — for open quotes — Eligibility.
- **Triage (D-15):** open quotes with `chase_eligibility = 'needs_review'` render with a leading checkbox column inside one form + one `Save eligibility` button (bottom, sticky-free, full-width on phone). Ticked = becomes chase-eligible on save; unticked stays `needs_review` (re-triageable). Explainer copy above the checkboxes. Checkbox tap target ≥44px row height.
- **Sync runs section:** last ~10 runs, table: time, outcome badge (`ok` → `.badge--ok`, failure kinds → `.badge--warn`/`.badge--error`), quotes fetched/updated counts, error detail line (classified reason only).

### 3. Auth-failed banner (D-05)
- New `.banner-error` block class: `--error` text + 1px `--error` border + 3px left border accent, `md` padding, `role="alert"`, full content width, sits under the page h1. Not dismissible. Rendered on the client detail page whenever `paused_at` is set with `status_reason='auth_failed'`.

### 4. Audits list + new prospect (`(console)/audits`, `(console)/audits/new`, D-12)
- **List:** table of prospects — business name (link), source (`API key` / `CSV`), created date, audit link. `New audit` accent button in the h1 `.row` (mirrors the clients page).
- **New:** business name field, then source choice as two radio options (`Read-only API key` — preferred, listed first / `CSV upload`). API path: key input identical in behavior to the client connect form (verify-on-submit). CSV path: file input (`accept=".csv"`, size-capped per RESEARCH), submit leads to the mapping step.
- **CSV mapping step (Pattern 7):** table of canonical fields (status, quote date, value, description, contact name/phone/email) each with a select of detected headers, pre-filled by heuristic; below it, a preview table of the first 5 parsed rows under the current mapping. Unmapped required field blocks `Confirm mapping` with the named-column error. This is the one interaction where the operator confirms an inference — never silently auto-map.

### 5. Quote Leakage Audit report (`(console)/audits/[id]`, D-09/D-10/D-11)
The sales artifact. One A4 page, phone-renderable, browser print-to-PDF.
- **Screen layout:** single column, max-width `42rem`, centered, `2xl` top spacing; console nav remains (operator context).
- **Print layout:** `@media print` hides `.nav` and any action buttons; `@page { size: A4; margin: 14mm }`; content budget MUST fit one page — verified by print preview during UAT. Force light colors; `print-color-adjust: exact` only where the accent figure needs it.
- **Content order:** title + subline → 2×2 figure grid (Quotes issued · Total quoted value · Value never followed up · **Recoverable estimate** — the accent-colored, 32px/600 hero of the page) → Baseline win rate as a one-line secondary stat (`{n}% of quotes won in the period` — AUD-02, understated on purpose: it's the later attribution baseline, not the pitch) → methodology footnote (14px, `--muted` on screen, black at reduced size in print) → footer line: service name + prepared date.
- **Figure grid on phone:** collapses to a single column (min-width ~360px works), figures stay 32px.
- No badges, no table of raw quotes, no interactive elements on the printed artifact.

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Applicable state considerations resolved: 11 covered, 2 backstop, 0 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | quotes table (never-synced / none-open / filtered-empty) | ✅ covered | Three distinct empty states with the documented copy — never-synced points at the connect form, filtered-empty names the active filter |
| empty | sync runs table, triage section, audits list | ✅ covered | Documented copy rows; triage section renders "Nothing needs review." rather than disappearing |
| loading | connect / re-key / mapping / generate submissions | ✅ covered | Server actions with pending-disabled buttons and pending labels (`Verifying key…`); pages are server-rendered so there are no client data-loading spinners |
| error | key verification, CSV mapping, audit generation, sync-run rows | ✅ covered | Classified-outcome copy per Copywriting Contract; inline `.field-error` next to the failing control (Phase 1 rule: top-of-form banners die under a phone keyboard); raw errors/keys never rendered |
| partial | CSV-sourced audit lacking notes/activity | ✅ covered | Report renders the CSV addendum footnote; degradation is stated, not hidden (D-10 honesty) |
| partial | CSV rows failing validation | ✅ covered | Proceed-with-warning copy (`{n} rows skipped`) before generation; operator confirms |
| zero-one-many | prospects, sync runs, needs-review quotes | ✅ covered | Empty copy defined; one row renders as the many-case table (no special casing); sync runs capped at last ~10 |
| overflow | quotes table on a large backfill (hundreds of rows) | 🧪 backstop | { statement: "The open-quotes table with 200+ backfilled rows remains scrollable and the triage Save button reachable on a 390px-wide phone viewport", verification: backstop } — founding-cohort scale makes pagination premature; verify with a seeded-large-tenant render during UAT |
| long-text | job descriptions / addresses in tables | ✅ covered | Truncate to one line with `text-overflow: ellipsis; max-width` on the cell; full text available on the (Phase 3+) quote view — tables never wrap into multi-line rows on phone |
| long-text | audit report business name / large dollar figures | 🧪 backstop | { statement: "The printed audit stays on one A4 page with a 60-character business name and 7-digit dollar values", verification: backstop } — verify via print preview with a worst-case fixture |
| populated | sync health badge ↔ banner consistency | ✅ covered | Both derive from the same `sm8_connections` fields (Pattern 5 derived-state rule) — badge `auth-failed` and banner can never disagree |
| error (color-only) | all badges and the banner | ✅ covered | Every state is spelled out in text; color is reinforcement, never the sole signal (WCAG 1.4.1) |
| overflow | dark-mode print | ✅ covered | `@media print` forces light values — a dark-mode phone printing the audit still produces ink-on-paper output |
