## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet → /api/internal/cadence-tick | anyone can POST; only the bearer distinguishes pg_cron |
| pg_cron/pg_net logs → operators of lower-trust surfaces | run history stores the HTTP outcome; response bodies may surface in logs |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-3-23 | Elevation | unauthenticated tick invocation (dispatch on demand) | high | mitigate | Length-guarded timingSafeEqual bearer; 401-no-Location test; proxy already excludes api/ so no redirect masquerades as success |
| T-3-24 | Information disclosure | customer/client data in tick responses or cron logs | medium | mitigate | Counts-only response asserted in tests; script prints job name + schedule only — see prohibitions |
| T-3-25 | Information disclosure | bearer secret leaked via script output or migration files | medium | mitigate | Secret-bearing schedules script-applied from env (Phase 2 A7 decision); command never printed |
| T-3-26 | Denial of service | per-minute tick overlapping a slow prior tick | low | accept | SKIP LOCKED claims + guarded updates make overlap safe (proven in 03-04); 300s maxDuration bounds each run |
</threat_model>
