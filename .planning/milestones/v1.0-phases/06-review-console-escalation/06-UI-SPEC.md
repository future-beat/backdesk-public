# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** the Phase 6 console surfaces — the cross-client approval queue (`/queue`, CON-01), the console nav count badge (D-10/D-12), the client-detail pipeline evolution + onboarding checklist card (CON-02, D-16..D-20), the client-list pending-drafts indicator (D-12), the quote-detail conversation thread (D-19), and the two operator-facing message templates this phase mints (the hot-lead SMS to the tradie, CON-03/D-07, and the stalled-draft alert/digest emails, CON-04/D-10/D-11). Sources: 06-CONTEXT.md D-01..D-20, 06-RESEARCH.md Patterns 1–8 + Pitfalls, the Phase 2 UI-SPEC (approved, still binding), and the shipped console conventions in `src/app/globals.css`, `src/app/(console)/inbox/page.tsx`, `clients/[id]/page.tsx`, and `quotes/[quoteId]/draft-review.tsx`.

**Design-system state: ESTABLISHED, not greenfield.** Phase 2's contract decided "do NOT introduce Tailwind/shadcn mid-project" and Phase 6 inherits that verbatim. This contract extends the existing class vocabulary; it invents new classes only where no existing one fits, and it never restyles a shipped rule.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — deliberate hand-rolled CSS system (`src/app/globals.css`), decided in the Phase 2 UI-SPEC and extended each phase since. Do not initialize shadcn/Tailwind |
| Preset | not applicable |
| Component library | none — semantic HTML + the existing class vocabulary: `.badge` (+ `--ok/--warn/--error` modifiers, hardened 05-08), `.touch-list`, `.touch-when` (+ `--stack`), `.touch-meta`, `.draft-review`, `.draft-card`, `.draft-body`, `.controls`, `.kill-armed`, `.kill-warning`, `.banner-error`, `.disclosure`, `.row`, `.meta`, `.muted`, `.hint`, `.error`, `.field-error`, `.cell-truncate`, `.table-scroll`, `.filters`/`.filter-link`, `.profile`, `.button`, `.linkish` |
| Icon library | none — status is always badge text + colour, never an icon, never colour alone (WCAG 1.4.1, established) |
| Font | System stack: `system-ui, -apple-system, 'Segoe UI', Roboto, sans-serif` (existing `body` rule). Message bodies in `ui-monospace, SFMono-Regular, Menlo, Consolas, monospace` via the existing `.draft-body` rule — "$2,450 and $2,540 look alike at a glance" |

**Theming:** light + dark via `prefers-color-scheme` custom properties (existing). Phase 6 declares **zero new colour tokens** — every state this phase renders maps onto the existing six-token pairs, both schemes already defined. Any new rule that hard-codes a hex instead of a `var(--…)` token is a contract violation.

**Component reuse mandate (mirrors RESEARCH Pattern 2 "extract, never copy"):** the queue card's approve / edit-then-approve UX is the existing `DraftCard` in `draft-review.tsx`, extracted into a shared component and *extended* (client-name header, urgency badge, skip control) — not a visual re-implementation. Two approval surfaces rendering the same draft must be pixel-identical in the parts they share, for the same reason the action core is shared: drift between them is the CR-02 defect class, in the DOM.

## Spacing Scale

Phase 2 rules carry forward unchanged. Existing shipped rules with ad-hoc rem values are **grandfathered — do not restyle**. All NEW Phase 6 rules use this scale (rem equivalents at 16px root):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (0.25rem) | Inline gaps inside `.touch-when` rows (badge ↔ timestamp — existing gap contract) |
| sm | 8px (0.5rem) | Gap between stacked controls (`.controls` existing 0.5rem), checklist row internals, chip gaps |
| md | 16px (1rem) | Default block spacing: between queue cards' internal blocks, checklist card padding, section gaps |
| lg | 24px (1.5rem) | Gap between pipeline groups on the client page, gap between queue cards |
| xl | 32px (2rem) | Reserved — major breaks only; not expected this phase |
| 2xl / 3xl | 48px / 64px | Reserved — not used this phase |

Exceptions:
- **44px (2.75rem) minimum touch target** on every button, the skip confirm, the disclosure summaries, and the nav Queue link's tap area (existing `button { min-height: 2.75rem }` + `.disclosure > summary { min-height: 44px }` rules). The queue is worked one-handed on a phone; nothing tappable may be smaller.
- **Phone-width stacking below 22.5rem** rides the existing `.touch-when--stack` modifier contract (05-08): full-row flex-basis, and `white-space: normal` relaxation on `.badge` inside it so a long pill wraps inside an intact border rather than overflowing. Queue card header rows adopt the same modifier where a client name + urgency badge must share a line.
- Existing shell (`main { padding: 1.25rem; max-width: 60rem }`) grandfathered.

## Typography

Weights for new work: **400 (regular)** and **600 (semibold)** — the Phase 2 rule. Existing 500-weight rules (`label`, `legend`) are grandfathered; no new 500 usage.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (1rem) | 400 | 1.5 (inherited from `body`) |
| Message body (`.draft-body`) | 15px (0.9375rem) | 400, monospace | 1.5 (existing rule — reuse, never redeclare) |
| Label / meta (`.meta`, `.touch-meta`, `.hint`, `.zone-note`) | 14px (0.875rem) | 400 (600 for the emphasized fact, e.g. `<strong>#3</strong>`) | 1.4 |
| Heading (h1 24px / h2 ~20px / h3 ~18px browser defaults inside the existing hierarchy) | 24px h1, defaults below | 600 | 1.2 |

Rules:
- Badge micro-type stays on the existing `.badge` rule (0.8rem uppercase) — reuse the class, never redeclare the size.
- **Timezone display:** send slots and touch schedules render in the TENANT's zone via `formatInTenantZone` with the zone named (existing house rule). The queue mixes tenants, so **each queue card names its own zone** (e.g. `Tue 2 Sep, 9:12 am (Australia/Perth)`) — the one-`.zone-note`-per-list shortcut only applies on single-tenant pages. Relative time-to-slot (`due in 2h 10m`) is zone-free and sits beside the absolute time, never instead of it.
- Counts and labels are rendered through **label maps, never `.replace('_', ' ')`** (house rule) — the new `operator_skipped` skip reason, the urgency tiers, and every checklist state get map entries that fail loudly on an unknown member.
- Numbers the operator compares (segments, counts) render as digits, not words; SMS segment counts reuse the shared `countSeptets`/`segmentCount` functions so the display and the refusal can never disagree (existing DraftReview rule).

## Color

Existing tokens (keep verbatim, both schemes): `--bg #ffffff/#101317`, `--fg #16181d/#e9ecf1`, `--muted #626875/#9aa2b1`, `--line #e2e5ea/#262b33`, `--accent #1f6feb/#6ea8fe`, `--error #b42318/#ff8a80`, `--ok #1a7f37/#57ab5a`, `--warn #9a6700/#d4a72c`.

**New tokens this phase: none.**

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--bg` | Page background, cards, form fields. Cards are drawn with `--line` borders, never fills (existing `.draft-card` convention) |
| Secondary (30%) | `--line` + `--muted` | Borders, group dividers, neutral badges, meta text, inactive states |
| Accent (10%) | `--accent` | Reserved list below |
| Destructive | `--error` | Reserved list below |
| Success | `--ok` | `.badge--ok` states only: `chasing`, `done`/satisfied checklist items, `hot` (existing inbox usage) |
| Warning | `--warn` | `.badge--warn` states only: `due soon` urgency tier, `awaiting approval` (existing), `stale — re-attest`, degraded health (existing) |

*(The Phase 2 note scoping `--ok`/`--warn` to sync-health badges is superseded by shipped Phase 5 usage — they are now the general badge-state trio. Border + text only; badge backgrounds stay `--bg`, per the shipped `.badge--*` rules.)*

**Accent reserved for:** links, the filled action buttons the existing `button` rule already paints (Approve / Approve my version / Edit this message / Record it's off), the active filter state, and the nav. Never for badges, urgency tiers, banners, chips, or the skip control.

**`--error` reserved for:** the `overdue` urgency tier and `stalled` badges (`.badge--error`), the STOP/opt-out badges (existing), the armed-kill outline (existing `.kill-armed` — still the only armed-destructive control; the queue's skip confirm does NOT go red, see Screens §1), error/`role="alert"` copy, and the `.banner-error` block.

**Urgency tier mapping (new, D-12 — fixed here, discretion exercised):**

| Tier | Predicate | Badge | Label text |
|------|-----------|-------|------------|
| Overdue | send slot ≤ now | `.badge--error` | `overdue` |
| Due soon | send slot within the stall threshold (4h — the SAME constant as the D-09 stall predicate, one rule asked twice) | `.badge--warn` | `due soon` |
| Scheduled | otherwise | `.badge` (neutral) | `scheduled` |

The tier badge is derived from ONE exported pure function shared with the stall policy (`deriveHealth` precedent: one derivation feeding every surface, so the queue tier, the nav badge and the alert email can never disagree about what "stalled" means).

Voice: plain, operator-facing, no jargon, no exclamation marks (established). Error copy = what happened + exactly what to do next. The hot-lead SMS is tradie-facing: their customer, their quote, plain words.

The phone number can never be clipped, because a clipped number is a lead the tradie cannot call — the entire product moment.

## Screens & Interaction Contract

### 1. `/queue` — cross-client approval queue (NEW page, CON-01)

- **Access & rendering:** `requireOperator()` before the read, `export const dynamic = 'force-dynamic'`, service-role read with names resolved via the operator's own JWT (inbox pattern verbatim). Denied and error states use the inbox's exact copy shapes (`role="alert"`).
- **Layout:** single column of `.draft-card`s, soonest send slot first (sorted in SQL before the cap — established rule), `lg` (24px) gap between cards. No pagination; capped read (~50) admits the most urgent by construction.
- **Card anatomy (top to bottom):**
  1. Header `.row`: `<strong>{Client name}</strong>` + urgency badge (tier table above). Client name via RLS lookup; unresolvable → `Another client` (inbox `nameOf` precedent).
  2. Meta line: `#{touchNumber} SMS · {slot in tenant zone, zone named} · due in {relative}` — quote description one line via `.cell-truncate`, linking to the quote page (the route into the full control surface; the kill switch lives there).
  3. **The full body, always:** `.draft-body` `<pre>`, the frozen `final_body` verbatim, un-truncated, monospace, `pre-wrap` — the full-review invariant made physical. No card state may collapse, clamp, or truncate the body of an approvable draft. Segments/model/attempt meta line under it (DraftReview verbatim).
  4. `.controls` stack, full-width 44px buttons: `Approve and send as written` (absent on failed drafts — server refusal mirrored, existing rule), `Edit this message` → inline edit form (shared DraftCard edit UX verbatim: pre-filled textarea in `.draft-body` face, live segment count via the same pure function, refusal hints), then the skip control.
- **Skip (D-02):** quiet style — new `.button-quiet` class (transparent background, `--line` border, `--fg` text, both schemes, 44px min-height) so it cannot be mistaken for approve and does not spend `--error` (the armed kill stays the console's only red control). Two steps: tap reveals the inline confirm row (copy above) with `Skip it` + `Keep it`; commit calls the new equality-guarded write. A stale card whose touch was approved elsewhere reports honestly (`This one was already approved.` — the zero-rows-updated re-read rule, Pitfall 3).
- **One at a time:** each card owns its own forms and pending state (`Approving…` disabled label — existing). No select-all, no approve-all, no keyboard bulk path, no per-client grouping controls (D-03, one-way).
- **After an action:** the card leaves the list on refresh (server action + revalidate); the nav badge self-corrects because server layouts re-render after actions (Pattern 8).

### 2. Console nav — Queue link + count badge (NEW, D-10/D-12)

- New `Queue` link second in the nav. Count badge is an existing `.badge` beside the link text (the nav is already a gapped flex container — the 05-08 `.badge` contract holds): neutral `.badge` with the pending count; `.badge--error` when any touch is stalled. Hidden entirely at zero — a permanent `0` trains blindness.
- Count read is **RLS-scoped via the caller's own JWT** (never service-role in the layout — the layout gates on auth, not operator; Pattern 8 / research A5). Count = touches in `needs_draft`/`pending_approval` on live cadences; stalled subset via the shared stall predicate.
- The badge is a count, not a colour signal alone: digits are the content, tier is reinforcement.
- **Count-read failure:** the nav renders with NO badge (same as zero) and the layout never breaks — the nav must always render; the honest error surfaces on the queue page itself (probe resolution, 2026-09-01).

### 3. `clients/[id]` — pipeline evolution + checklist card (D-16..D-20)

- **Section order (single column, phone-first):** back link → h1 `.row` + status badge → auth-failed banner (existing, when applicable) → profile `dl` (existing) → **`Ready to send?` checklist card (NEW)** → `Voice & templates →` link (existing) → ServiceM8 connection (existing, unchanged) → **Quotes (pipeline, evolved)** → Needs review triage (existing, unchanged) → Recent sync runs (existing, unchanged).
- **Checklist card (D-16):** `.draft-card`-bordered block. Six rows (labels fixed in Copywriting) as `.touch-list` items: item label + state — satisfied → `.badge--ok` `done` (or the actual fact where one exists: the contact window with zone, the armed channel); unmet → `.badge--warn` + the fix link. Only `ServiceM8 auto follow-up off` is attested: unmet shows the `Record it's off` disclosure with the required-note form; met shows the attested line + stale badge when ≥30 days. Derived items are computed from the same condition readers the gate uses — display and gate can never disagree (the `deriveHealth` one-derivation rule).
- **Pipeline (D-17/D-18):** the quotes section regroups by cadence state in action order under h3 headings — `Needs attention` (paused / triage / stalled) → `Chasing` → `Waiting` → `Closed` collapsed in a `.disclosure` (`Closed ({n})`). The Open/Won/Lost/All `?status=` filter is superseded by the grouping (Closed holds won/lost history). `Needs attention` always renders, with `Nothing needs attention.` when empty; `Chasing`/`Waiting` render only when non-empty; `Closed` renders whenever it has rows.
- **Row shape:** groups render as `.touch-list` rows, not the seven-column table — the shipped "A LIST, NOT A TABLE" phone decision, and these rows carry more facts than the table can hold at 390px. Per row: job # link (the stable tap target — existing rule) + one-line `.cell-truncate` description + value → **next-touch line** (D-20 copy) → **compact chips** (D-19): `sent {relative}` + `reply — {guess phrasing}` label chip. Chips are indicators only; bodies stay on the quote page and inbox (T-2-02 discipline). Timestamps in the tenant zone; the zone named once in a `.zone-note` beside the Quotes heading (single-tenant page — the existing shortcut applies here).
- **Weekly summary line (D-20):** `{n} touches scheduled this week`, `.muted`, under the h2.

### 4. Client list `/` — pending-drafts indicator (D-12)

- One new `Drafts` column in the existing table: pending count as a `.badge` (digits), `.badge--error` when any of that client's touches are stalled, `—` at zero. Derived from the same shared stall predicate. No new row styling. `[Contract correction 07-07, 2026-09-03, G-07-6: this row asserted a .table-scroll wrapper the client list never had — the table at src/app/(console)/page.tsx was a bare child of <section> from the 01-02 tracer until 07-07; .table-scroll began on the quotes table (02-05, 8de755c); at 390px the seven-column table widened the document to 620px.]`

### 5. `clients/[id]/quotes/[quoteId]` — conversation thread (D-19)

- New `Conversation` section on the quote page (where the cadence controls already live): sent touches interleaved with replies as `.touch-list` rows, oldest first, timestamped in the tenant zone (zone in the section's `.zone-note`). Sent rows: `#{n} sent {time}` + delivery badge where known; reply rows: the body verbatim (this page is inside the operator gate — the inbox rule extends here) + label guess chip. Raw bodies render here and the inbox ONLY; never in chips, logs, or emails.

### 6. Messages that are UI (CON-03 / CON-04)

- **Hot-lead SMS:** exact template + truncation rule in Copywriting. It is a lead-conversion artifact: reply text + tap-able number (a bare `+61…`/`04…` number auto-links on every handset; no URL, no dashboard reference — tradies never see a dashboard).
- **Stalled alert + digest emails:** subjects/bodies in Copywriting; closed-vocabulary builder exported and asserted verbatim (T-2-16 precedent); the only link is the queue URL.
