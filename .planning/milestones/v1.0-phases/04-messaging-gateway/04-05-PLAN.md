## Trust Boundaries

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-4-19 | Elevation | unsubscribe as suppression oracle (suppress arbitrary victims) | high | mitigate | Token is an HMAC over (tenant, cadence) minted only at send time — possession implies receipt of the email; no address- or id-based path exists |
| T-4-20 | Info disclosure | address enumeration via response differences | high | mitigate | Byte-identical responses for valid/invalid/repeat; GET page identical for any token; strict-equality response test |
| T-4-21 | Spoofing | token forgery | high | mitigate | HMAC-SHA256 with dedicated ≥32-byte secret (own secret per the two-bearer precedent); constant-time verify |
| T-4-22 | Spoofing | email sender spoofing / deliverability | medium | mitigate | SPF/DKIM via Resend verified domains only; the sender refuses the owner-only resend.dev path for client mail |
| T-4-23 | Repudiation | one-click bots (mail scanners) unsubscribing a real recipient | low | accept | RFC 8058 semantics accept this industry-wide; over-suppression is the compliant failure mode (D-03 philosophy) |
| T-4-SC | Tampering | package installs | low | accept | No package-manager installs — resend@6.22.1 stays pinned (research legitimacy audit: upgrade only with a human-verify checkpoint; none needed this plan) |
</threat_model>
