<objective>
Close VERIFICATION gap 2 (CR-01): per-tenant messaging activation is currently unreachable.
`buildRoutingSender` gates both channels on the GLOBAL `messaging_config` row only
(routing-sender.ts:228-231 call `getChannelConfig` with no tenant argument), so enabling a single
client's row with the global row off yields `StubSender` silently — `sender='stub'`,
`outcome='stub_sent'`, nothing sent — while the console reports success. The only working
activation arms every client at once: the exact inverse of the D-04 rollout the
`messaging_config` table exists for.

Fix per 04-REVIEW.md CR-01: a deployment-level "any enabled row for this channel" gate
(`anyChannelEnabled`), with the per-tenant resolvers remaining the identity authority. Also
corrects the two false claims the gap's artifacts name: the routing-sender.ts:119-124 header
comment (IN-04) and the settings/email success copy (actions.ts:292).

Purpose: the first real client cannot be armed one-at-a-time until this lands (D-04); MSG-02's
per-tenant email enable is broken without it.
Output: corrected gate + resolvers-as-authority, rewritten comment, honest console copy, and the
tenant-override activation test the gap requires.
</objective>
