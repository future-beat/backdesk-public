**Consequential edits the token swap forces (contract, not optional):**

1. `button` and `.button` in `globals.css` currently hard-code `color: #fff`. Change both to `color: var(--accent-fg)`. White on the dark accent `#4CBF86` is ~2.1:1 and would fail on the operator's phone; `#101317` on it is 8.1:1.
2. `src/app/(console)/audits/[id]/audit.css` line ~123 overrides `--accent: #1f6feb` for print. Change to `#1B7A4A` so the printed audit's big figures are Recovered green (D-07).
3. Add `font-variant-numeric: tabular-nums` to every dollar figure rule in `audit.css` and `report.css` that does not already carry `.num` (D-07). No other change to the A4 pages.
4. Any new rule that hard-codes a hex instead of a `var(--…)` token is a contract violation. The single permitted literal is the OG image, which is rendered once to a PNG and is always light.

**Known, accepted side effect:** `--accent` (`#1B7A4A`) and `--ok` (`#1A7F37`) are now near-identical greens. Console links and `.badge--ok` will read as the same colour. M1 keeps ok/warn/error unchanged on purpose; do not "fix" this by tinting either token.

## Spacing Scale

Declared values (multiples of 4; rem at a 16px root). Existing console rules with ad-hoc rem values are grandfathered; every **new** rule uses this scale.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (0.25rem) | Gap between a label and its hint; badge internal gap |
| sm | 8px (0.5rem) | Gap between a hint and its input; stacked meta lines; gap between inline badges |
| md | 16px (1rem) | Default block gap: between form fields, between paragraphs, card padding on phone |
| lg | 24px (1.5rem) | Card padding at ≥ 48rem; gap between step items and between tier cards; header vertical padding |
| xl | 32px (2rem) | Gap between a section heading and its first block; gap between hero lede and the CTA |
| 2xl | 48px (3rem) | Vertical padding of each landing section on phone |
| 3xl | 64px (4rem) | Vertical padding of each landing section at ≥ 48rem; footer top padding |

Exceptions:
- **44px (2.75rem) minimum touch target** on every button, link-as-button, form control, select and file input, on both the public pages and the console (D-19; existing `button { min-height: 2.75rem }`). The landing primary CTA is **48px** tall (3rem) so it reads as the page's one action at thumb reach.
- **Page gutter 20px (1.25rem)** on phone, matching the console `main` padding so the shared header and footer align across hosts. 20 is on the 4px grid.
- **Max measure 38em** on every prose block (M1 §3: `max-width: 38em` at the body size, ≈ 646px). Pricing cards, the header and the footer sit inside a wider `64rem` wrap.
- Wordmark clear space = cap height on all sides (M1 §4); in the site header the lockup PNG's own canvas margin supplies it (C-1), elsewhere it is padding, never a token.

## Typography

Two text weights: **400** (body) and **600** (headings, labels, emphasis). **700 is brand-locked to exactly two things** and is not a third text weight: the wordmark glyphs (Inter Tight 700, M1 §4) and standalone dollar figures (M1 §3 "Dollar figures 700 in Recovered green with tabular numerals").

Marketing pages (Inter):

| Role | Size | Weight | Line Height | Notes |
|------|------|--------|-------------|-------|
| Body | 17px (1.0625rem) | 400 | 1.55 | M1 "17–18px on phone" locked at 17px at every width. Max measure 38em |
| Small (labels, hints, captions, footer, badges, meta) | 15px (0.9375rem) | 400; labels 600 | 1.4 | Never below 15px on public pages; form inputs stay ≥ 16px to stop iOS zoom (see Form spec) |
| Heading (`h2` sections, `h3` step and tier titles at body size) | 24px (1.5rem) `h2`; `h3` = 17px 600 | 600 | 1.2 | `letter-spacing: -0.02em` on `h1`/`h2` only |
| Display (`h1`, price figures) | 32px (2rem) phone; `h1` 40px (2.5rem) at ≥ 48rem | `h1` 600; price figures 700 | 1.15 | Price figures: `--accent`, `font-variant-numeric: tabular-nums`, never larger than `h1` |

Wordmark: text `Backdesk`, `font-family: var(--font-inter-tight), Inter, Arial, sans-serif`, 700, 24px where it is rendered as text — audit, report, email, console (≈100px wide, above the 96px minimum; the site header uses the lockup image per C-1), `letter-spacing: -0.03em`, `font-variant-ligatures: none`, colour `var(--fg)`. Never green, never with a tagline inside the element, no shadow or gradient (D-05).

Console (system-ui, unchanged sizes): body 16px/400/1.5; `h1` 24px/600; meta 14px; badge 0.8rem uppercase (existing rules; do not redeclare).

Rules:
- Sentence case for every heading and button. No exclamation marks. No em dashes in any rendered string (M1 punctuation rule; use a full stop, comma or colon). En dashes in numeric ranges are fine (`8–15`, `$2k–50k`).
- Numbers as digits with the dollar sign and the multiplication sign: `$597 / month`, `3×`, `90 days`.
- `ServiceM8` with capital M and digit 8; `Backdesk` one word, capital B.
- Dollar amounts inside running prose (`$2k–50k` in "A good fit") stay `--fg` at body weight with `tabular-nums`; only **standalone** figures (price table, founding-five price) take green 700.

## Color

60/30/10 on the landing page, both schemes:

| Role | Value (light / dark) | Usage |
|------|----------------------|-------|
| Dominant (60%) | `--bg` `#FAFAF7` / `#101317` | Page background of every marketing and console page; the hero sits on it with no panel |
| Secondary (30%) | `--surface` `#FFFFFF` / `#181C22` | Tier cards, founding-five and guarantee callouts, form inputs, console request detail cards. Always with a `1px solid var(--line)` border and 8px radius; never a shadow |
| Accent (10%) | `--accent` `#1B7A4A` / `#4CBF86` | See reserved list below and nothing else |
| Text | `--fg` Ink / `--muted` Slate | Headings and body in Ink; captions, hints, footer, eyebrow, table headers in Slate |
| Destructive / error | `--error` `#B42318` / `#FF8A80` | Field errors, form-level errors, the rate-limit refusal, the console `notify failed` badge. No destructive action exists in this phase |

**Accent reserved for (exhaustive):**
1. The **one primary action per page**: `Get the free audit` on `/`, `Request the free audit` on `/audit`, `Start audit` on the console request detail. On `/` the same action is rendered twice (hero and closing "How to start" section); it is still one action and no other green button may appear on the page.
2. **Standalone dollar figures**: the four price figures in the tier cards and the `$297 / month` founding-five figure. (Example figures, if the 11 Sep copy adds one to the hero, render the same way and carry the word "example".)
3. **Text links** in body copy and the footer (M1 colour table: "links"; existing global `a { color: var(--accent) }`). Links are always underlined so colour is not the only cue.
4. **Focus rings** (`outline: 2px solid var(--accent); outline-offset: 2px`, the existing console convention). Non-text contrast on Paper 5.1:1, on white 5.3:1.

Accent is **never** used for: the header, borders, section backgrounds, badges, step numbers, the wordmark, icons (there are none), the secondary button, hover tints, or the selected state of a radio/select.

**Contrast (from the M1 table, all AA for body text):** Ink on Paper 15.3:1; Ink on white ≈ 16:1; Slate on Paper 5.7:1; Slate on white ≈ 5.9:1; green on Paper 5.1:1, on white 5.3:1; white on green 5.3:1; error on Paper 6.3:1. Dark: `#E9ECF1` on `#101317` ≈ 14:1; `#9AA2B1` on `#181C22` ≈ 6.7:1; `#4CBF86` on `#101317` 8.1:1; `#101317` on `#4CBF86` 8.1:1.

**Form-field boundary contrast (new rule):** `--line` on Paper is ≈ 1.3:1, below the 3:1 non-text minimum (WCAG 1.4.11). Marketing form controls therefore use `border: 1px solid var(--muted)` (5.7:1). Console inputs keep `--line` (grandfathered, operator-only).

## Accessibility Contract (D-19)

- Landmarks on every page: `header`, `nav[aria-label="Site"]`, `main#main`, `footer`; a visually-hidden-until-focused skip link as the first focusable element.
- Exactly one `h1` per page; heading levels never skip (`h1 → h2 → h3`).
- Every control has a `<label for>`; radio groups sit in a `fieldset` with a `legend`; hints and errors are bound through `aria-describedby`; invalid controls carry `aria-invalid="true"`; error paragraphs carry `role="alert"`; the form-level message carries `role="alert"`, success/status messages `role="status"`.
- Visible focus on every interactive element: `outline: 2px solid var(--accent); outline-offset: 2px` (existing convention), never `outline: none`.
- Colour is never the only cue: links are underlined, errors have text, badges have words.
- Target size ≥ 44×44px for every button, link-as-button, input, select, radio label (`.check` rows, 44px tall) and file input. Header text link 44px tall.
- Contrast per the M1 table (Color section). Form borders use `--muted` to meet 3:1 non-text.
- `html lang="en-AU"` (existing). `inputmode` and `autocomplete` on every form field so phone keyboards are right.
- No motion, so `prefers-reduced-motion` has nothing to disable; keep it that way (no scroll-triggered effects, no carousels).
- Text reflows at 320px with no horizontal scroll; the wordmark and header link fit one row at 320px.
- Lighthouse accessibility ≥ 90 mobile on `/` and `/audit`; record the numbers in the phase verification (D-18).
