<objective>
Two refinements of the tracer's arming slice. First, the SMS control names the clients it will arm: the two-step warning and the success sentence carry the count and names of every connected client that has no sms row of its own, which is exactly the set the shared row governs — and the list is how the operator sees the Phase 4 test tenant sitting there before it has its explicit off override. Second, the email settings form stops being an unaudited arming path: it saves identity only and preserves the stored `enabled`, so every flip of `enabled` goes through the audited client-page action; its verified-domain check now calls the one predicate the checklist uses.

Purpose: D-03 requires the control to state plainly that it arms every connected client; naming them makes the statement checkable. D-04 requires every arm/disarm to be audited; a second, unaudited path in settings would make that false.

Output: `forAllTenants_armedBySmsGlobal`, the enriched warning/sentence, the identity-only settings action and form, and the updated settings suite.
</objective>
