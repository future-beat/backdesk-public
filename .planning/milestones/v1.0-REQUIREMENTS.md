# Requirements — Quote Recovery MVP

**Defined:** 2026-08-25
**Source:** GTM plan (The Quote Recovery Playbook) + project research (.planning/research/)

## v1 Requirements

### Tenancy & Onboarding

- [x] **ONB-01**: Operator can create a client (tenant) with business profile, trade type, timezone, and contact-hours window
- [x] **ONB-02**: Operator can connect a client's ServiceM8 account (private API key now; OAuth when partner approval lands) and see sync health per client
- [x] **ONB-03**: Operator can capture a client voice profile and approve per-touch message templates; no cadence can activate before templates are client-approved
- [x] **ONB-04**: Onboarding checklist blocks cadence activation until ServiceM8's native Quote Follow Up automation is verified off, and the check re-runs periodically for drift
- [x] **ONB-05**: All data access is tenant-scoped — RLS on all tables plus a tenant-scoped query layer for service-role workers, with cross-tenant leak tests in CI

### ServiceM8 Sync

- [x] **SYNC-01**: System syncs jobs in status Quote (value, contact, dates) per client via edit_date-cursor polling, inside ServiceM8 rate limits (180/min, 20k/day)
- [x] **SYNC-02**: System detects status transitions (Quote → Work Order/Completed = won; Quote → Unsuccessful = lost) and emits events the cadence engine consumes
- [x] **SYNC-03**: Webhooks, when available, act as hints-to-poll (fetch on notify) with UTC/account-local timestamp normalisation — polling remains the guarantee
- [x] **SYNC-04**: Sync/auth failures (e.g. invalid_grant, key revoked) pause that client's cadences and alert the operator immediately

### Quote Leakage Audit

- [x] **AUD-01**: Operator can generate a one-page audit from a prospect's ServiceM8 read access or CSV export: last-90-days quotes issued, total value, never-followed-up value, recoverable estimate
- [x] **AUD-02**: Audit snapshots the prospect's baseline win rate, stored for later net-of-baseline attribution

### Cadence Engine

- [x] **CAD-01**: Every synced open quote gets a cadence of up to 5 touches over ~3 weeks, with per-touch channel (SMS/email) and timing from the client's approved template set
- [x] **CAD-02**: Touch send times are materialized, contact-hours- and timezone-aware; overdue touches re-window to the next allowed slot rather than sending late
- [x] **CAD-03**: Cadences stop or pause deterministically on: customer reply, quote won/lost, opt-out, and operator kill switch (per-contact and per-client)
- [x] **CAD-04**: Sends are idempotent via a send ledger with a unique constraint — a quote can never receive the same touch twice
- [x] **CAD-05**: Dispatch revalidates quote status, suppression list, and send window just-in-time before every send (stale sends are impossible by construction)

### Messaging Gateway

- [x] **MSG-01**: SMS sends and receives via dedicated AU virtual number(s) with two-way replies and delivery receipts recorded per message
- [x] **MSG-02**: Email sends via verified client domain (or service-subdomain fallback) with SPF/DKIM, Spam Act-compliant sender identification and functional unsubscribe — pipe built and unit-tested; live proof deferred by override to first-client onboarding (blocked-external: no client domain), see the `overrides:` entry in .planning/phases/04-messaging-gateway/04-VERIFICATION.md. Flips only when the real send is recorded in docs/external-registrations.md
- [x] **MSG-03**: STOP/unsubscribe processing is deterministic (regex before any LLM), spans SMS and email per contact, and takes effect immediately at the send gate
- [x] **MSG-04**: Every outbound message identifies the client business; every inbound message threads to the correct tenant, contact, and quote

### AI Drafting & Classification

- [x] **AI-01**: Claude drafts each touch from the client's voice profile and approved template using merge fields — prices, dates, and names come from data, never from the model
- [x] **AI-02**: Inbound replies classify into a closed enum (interested / question / objection / not-interested / opt-out / other) via structured output; low-confidence classifications route to the operator
- [x] **AI-03**: Inbound content is treated as untrusted input — templates constrain drafting, classification is schema-only, and no inbound text can alter system behaviour directly
- [x] **AI-04**: Every draft records model, template/prompt version, and human edit distance — the edit-rate dataset that later justifies graduated autonomy

### Review Console & Escalation

- [x] **CON-01**: Operator can work a mobile-friendly approval queue: approve, edit-then-approve, or skip each pending draft; full-review mode is the default for a client's first 30 days
- [x] **CON-02**: Operator can view per-client pipeline: open quotes, cadence states, recent messages, and upcoming touches
- [x] **CON-03**: Hot replies (interested/question) SMS the tradie within minutes, including conversation context
- [x] **CON-04**: The queue surfaces draft aging against the first-touch-within-24h target, and stalled drafts alert the operator

### Reporting & Instrumentation

- [x] **RPT-01**: A job won after ≥1 sent touch within the attribution window counts as recovered revenue (gross), reported alongside a conservative net-of-baseline figure
- [x] **RPT-02**: Operator can generate a per-client monthly report (web/PDF): quotes chased, replies, jobs won, dollars recovered (gross + conservative), fees paid, multiple returned
- [x] **RPT-03**: System tracks per client: first-touch-within-24h rate, reply rate, opt-out/complaint rate, human-edit rate, and recovery multiple

## v2 Requirements (Deferred)

- **V2-01**: Sampled-review / graduated autonomy — trigger: per-client edit rate <~10–20% for 30 days
- **V2-02**: AI-suggested replies to customer responses (human-approved) — trigger: reply volume makes escalate-everything burdensome
- **V2-03**: Quote-viewed triggers — pending ServiceM8 exposing view events reliably
- **V2-04**: Cross-client benchmarking in reports — trigger: ≥10 clients of data
- **V2-05**: Missed-call text-back — needs per-client number provisioning (GTM freebie, not the core)
- **V2-06**: Voice follow-up — only if text cadence proves out
- **V2-07**: Simpro/AroFlo integrations — wait for demand; CSV bridges
- **V2-08**: Client-facing read-only report portal — when email/PDF distribution becomes friction

## Out of Scope

- Lead generation of any kind — the service converts existing demand; mixing blurs the measurable claim
- Full CRM / contact management — ServiceM8 is the system of record
- Visual workflow builder — cadences are code + config, not a builder product
- A/B testing and open-rate tracking — premature at 5–15 clients; adds tracking complexity
- Client logins/dashboards in v1 — clients get reports, not another app to learn
- Payment/billing automation — direct debit handled manually at founding-cohort scale
