# Quick Task 260827-n16: Fix CI — Provide RESEND_API_KEY and OPERATOR_ALERT_EMAIL Summary

CI on main was aborting before a single test ran because `tests/helpers/env.ts` has listed `RESEND_API_KEY` and `OPERATOR_ALERT_EMAIL` as REQUIRED since task 02-04, while `ci.yml` never exported them; both now ship as self-describing dummies in the workflow's `GITHUB_ENV` block, and `docs/env-vars.md` — the contract the error message cites — documents the convention and the keep-in-sync rule.

## What Was Built

**Task 1 — `.github/workflows/ci.yml`** (commit `769bcc2`)

Two exports added to the `{ ... } >> "$GITHUB_ENV"` block of the "Export local stack environment" step, directly after the existing operator-credential dummies:

- `RESEND_API_KEY=re-ci-not-a-secret` — `z.string().min(1)`, so any non-empty string passes; the value names itself as a non-secret.
- `OPERATOR_ALERT_EMAIL=alerts@ci.invalid` — `z.email()`, so the dummy had to be a syntactically valid address. The reserved `.invalid` TLD satisfies the parser while guaranteeing the address can never resolve or deliver.

A comment in the style of the neighbouring "Dummy operator credentials" note records why the values are fake and forbids replacing them with real credentials inline (a suite that genuinely needs to send takes a repository secret).

**Task 2 — `docs/env-vars.md`** (commit `3167a6a`)

New "How CI supplies these variables" subsection under "Running the tests", covering: which vars come from `supabase status` versus which are dummies; why fakes are safe (the `onAlert` spy in `tests/sync-failure-alerts.test.ts` means the Resend path is never exercised); and the keep-in-sync rule — a new name on the REQUIRED list must gain a matching `GITHUB_ENV` entry **in the same commit**.
