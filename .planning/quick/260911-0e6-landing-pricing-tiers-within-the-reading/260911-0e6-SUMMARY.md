# Quick 260911-0e6: pricing tiers within the reading measure — Summary

**The pricing cards now stop at the same 38em column edge as every other block in their section (x=874 on a 1440px screen), because the grid box the `1fr 1fr` fractions divide is finally capped — the tracks went from `480px 480px` to `311px 311px` with no change to the track list itself.**

## Accomplishments

- **Found that the plan's stated cause was not the cause.** The plan expected to replace "any fixed pixel or minmax track that produces 480px columns". No such track existed — `grep -c "480px"` on the stylesheet was already 0 before any edit, and `grid-template-columns: 1fr 1fr` was already in the 48rem block. `480px` was a *computed* value: `.wrap` is 64rem with a 20px gutter (984px), less the 24px gap, halved. The bug was the absence of a cap on the box being divided, not the presence of a bad track.
- **Capped `.marketing ul.tiers` at `38em`** — the same value and spelling `.measure` and `.callout` use — leaving the existing `margin: 0 0 24px` to keep it left-aligned on the container edge rather than centred.
- **Proved the fix at three viewports, locally and then live**, including the tablet band that justified the placement decision.
- **Added five contract gates, each mutation-checked**, so the three plausible regressions (drop the cap, centre the capped box, hard-code a px track) each fail a distinct named assertion.

## Decisions Made

**1. The cap goes on the base rule, not inside `@media (min-width: 48rem)`.**
The must-have truth says the phone stays "unchanged", which argues for a desktop-only cap. But measurement shows the cap is *inert* until the viewport passes ~686px (below that the container is narrower than 38em anyway), and in the 686–768px band the section's own prose is already capped at 38em. A desktop-only cap would therefore leave exactly the same overhang on a landscape tablet — the bug this task exists to remove, at a different width. Verified at 728px: `.tiers` and `.callout` both render 646px wide with matching edges. The plan's own action text ("give `.marketing .tiers` `max-width: 38em` and, *inside the existing media block*, set `grid-template-columns`") assigns the two properties to the two places this way.

**2. The width gate compares boxes, not literals.**
`expect(tiers.maxWidth).toBe('38em')` alone would let someone retune `.measure` to 34em and silently push the prices back out of the column. The test also asserts `.tiers`'s cap equals `.measure`'s and `.callout`'s, because "the same column" is a relationship between siblings — `.callout` is the grid's next sibling inside the same `.wrap`, so equal caps on two left-aligned boxes *is* the "right edges line up" claim, expressed in source.

**3. Selector left as `.marketing ul.tiers`.**
The plan writes `.marketing .tiers` throughout. The stylesheet has used `ul.tiers` since Phase 9. Renaming is scope the fix does not need, and the prohibition on this task is explicitly about staying confined to `.tiers`.

**4. No `white-space: nowrap`.**
The plan made this conditional on measurement ("only if measurement shows a wrap"). At 311px cards the `.price` line renders as a single 36.8px line box in both cards and each `.figure` Range yields exactly 1 client rect. The condition did not fire, so nothing was added.
